# Agent 知识卡片编写与审校

本规范承接 `vendor/phase4_content_generator.py` 的概念定义、规则、对比、易错点和 Cornell 配对要求，供不会执行该提示词的 `--agent-content` 工作流使用。复用 v2 及现有渲染字段，不增加语义解析器或模型调用。字段长度和数量不是教学质量的替代品。

## 从题目归纳到卡片

1. 阅读全部原文件，保留原题、答案和解析的来源区别。先列每题真正考查的规则与条件，再确定知识点边界。
2. 保存简短工作清单：知识点名称及范围、关联题号、合并或独立的理由、对应证据、未解决事项。可以用表格或 Markdown，不是另一个导入 schema。共用规则的多题应复用知识点；一题考多个独立概念可多重关联。不要按题号机械批量建卡，也不要为降低卡数而合并无关内容。
3. 对每个拟写的关键结论确定支持范围：题库原解析、教辅直接支持、仅相关教辅、Agent 推导或无法核验。检查原页，而非只用搜索命中的一句话判定支持。
4. 选择有代表性的初始样本进行编写和自审，覆盖实际出现的不同题型以及冲突、图表或缺证据案例。样本通过下方审校表后再展开批量。任务只有一张卡时审这一张；无需用户重复批准。
5. 批量完成后逐卡审校，并修正审校发现的问题。脚本可以组装已编写内容，不能以“把原解析复制到模板”替代知识讲解。

## 根据知识点决定需要讲什么

| 类型 | 学习者看完应能做到 | 现有字段落点 |
| --- | --- | --- |
| 概念与分类 | 解释概念、按依据分类、区分相近类型及边界 | `core_concept.definition/rules/type_comparison/comparisons` |
| 计算方法 | 解释变量、选择适用公式、执行步骤、解释结果并识别误用 | `core_concept.definition/syntax/rules`、`common_mistakes` |
| 管理过程 | 解释目的、关键输入输出及工具作用、区分相邻过程 | `core_concept.definition/principle/syntax/rules/comparisons` |
| 单一事实 | 准确回忆事实，理解材料限定的背景、版本或时间 | `one_liner`、简短 `core_concept.definition` 与 Cornell 配对 |

正文应覆盖关联题目的实质考点。规则和易错点应来自原文或可明确解释的题目推导；没有对比对象时无需硬造对比，没有实践依据时不要写成“官方推荐”。`best_practices`、`mnemonic`、图表、可视化和别名按真实用途提供，不能为了凑字段而补充无依据内容。可视化只表达正文已说明的关系。

逐卡判断六项学习辅助模块，并写入 `learning_support_review`。键为 `mnemonic`、`visualization`、`principle`、`comparisons`、`best_practices`、`why_tested`；每项填写 `status`（`included`、`not_applicable`、`insufficient_evidence`）和针对本卡的具体 `reason`。`included` 表示对应展示字段已有实质内容，不能靠审校元数据代替正文。`principle` 对应 `core_concept.principle`；`comparisons` 可由 `core_concept.comparisons` 或 `core_concept.type_comparison` 承载。`insufficient_evidence` 用于值得讲但来源暂不足的情形，并在可见正文或交付说明保留限制；单一事实无可讲的结构时可以判 `visualization: not_applicable`。无助记价值时可以不写口诀，不能把别人的口号或无依据的技巧硬塞入卡片。整个学习包若图谱或口诀为零，质量报告会要求复核整体覆盖，避免批量遗漏被逐卡豁免掩盖。

示例（理由须改为本卡实际判断，不能批量复制）：

```json
"learning_support_review": {
  "mnemonic": {"status": "included", "reason": "三步顺序容易混淆，口诀只帮助记住已核实的顺序。"},
  "visualization": {"status": "included", "reason": "三个阶段存在前后关系，流程图可帮助复述。"},
  "principle": {"status": "included", "reason": "题目要求解释批准前不能实施的机制。"},
  "comparisons": {"status": "not_applicable", "reason": "本卡只讲同一流程，没有独立对比对象或类型变体。"},
  "best_practices": {"status": "insufficient_evidence", "reason": "资料仅描述流程，未给出可核验的操作建议。"},
  "why_tested": {"status": "included", "reason": "关联题考查批准节点与实施顺序。"}
}
```

若卡片要给出前置、后续或相关学习路径，使用现有 `learning_relations` 的显式关系，并核对两端知识点与学习理由。章节顺序、题号顺序和邻近页面都不能自动推成前置关系。

计算卡首次说明变量全名与缩写，明确公式条件，全文使用一致的公式表达。需要多种公式时按适用情形区分，不能把某一题的特定假设写成普遍结论。图示数值必须核验原页；自行演算的例子标为 Agent 演算并核算结果。计算和图表卡须另作一遍独立推导，记录关键中间值与约束，不能只核对最终选项是否一致。网络图尤其检查全部紧前、紧后关系与最早开始/完成时间；第一次推导中的误值可能碰巧不改变最终答案。发现错误时同步修正题目解析、正文、公式、自测和摘要。

## 独立复习与迁移检查

计算和方法卡先建立可独立复习的知识骨架，再将原题作为应用例子：讲清概念、适用条件、一般步骤和有证据的易混边界。确定范围时回看相关教辅上下文，纳入理解或迁移本方法所必需的相邻概念，不以当前一道题的解答范围作为知识点上限，也不把整章无关内容塞入单卡。扩展讲解不自动增加题目关联。

自审时暂时去掉题号、选项和本题数值：读者是否仍能解释方法，并判断换一组条件时怎样使用？若剩下只有名称或定义，仍是例题解答，应补正文后再标 reviewed。另用一个改变条件的口头问题检验迁移，例如多个前序汇合时该取最大还是最小；答案须来自已核实规则或明确标注的推导，无需编造新真题。审校 rationale 记录具体迁移检查及其条件。单一事实卡不强制套用此方法卡标准。

## 围绕核心知识点适度扩展

规划每张卡时判断是否需要扩展，选择能解释原理、辨别易混概念或迁移解题的相邻知识。先完成核心讲解，再决定扩展；同章、同关键词不是收录理由。不规定扩展数量或字数，单一事实卡或无可靠依据时允许不扩展。

- **核心考点**：关联题目直接考查的概念、一般方法及理解它必需的条件。不能把必要条件藏到可选扩展里。
- **扩展理解**：帮助解释“为什么”、比较边界或判断条件变化的知识。写清它与核心知识的关系及用途，例如“用于区分两种资源调整措施”。
- **延伸学习**：形成另一个独立学习目标、需要较多前置知识的内容。可简短提示进一步学习方向；仅在现有契约支持且证据充分时另建卡并使用受支持的关联方式。不要为延伸卡虚构题目关联。

### 依据与范围

逐项核对扩展结论的支持范围。在工作清单中记录“扩展主题—学习用途—来源文件/物理页与支持片段，或推导所用已核实前提”。教辅有直接支持时沿用 evidence 关联；页面上的扩展文字也说明所依据的材料和页码，便于对应到本卡教辅入口。只有相关段落不能标为 supports。

Agent 推导须在可见文字中标注，并写出前提和适用条件；不能把凭记忆补充的知识包装为推导。尚无依据的可选扩展先不作为确定知识或自测答案，只在确有学习价值时列为待核实方向；保留有限结论或存在冲突时，按证据与缺口规则标记并报告。不因“扩展”而放宽核验，也不自动外搜以填满卡片。

扩展主题不自动成为关联题目的考点，不自动增加 question↔concept 关系。题目关系仍由原题实际考查内容确定；同样不能无依据宣称扩展是“高频”“必考”或属于当前考纲。

### 使用现有字段分层呈现

沿用 v2 字段，不新增渲染器未支持的 `extended_knowledge` 等字段。`one_liner` 与 `core_concept.definition/syntax` 优先讲核心；在 `core_concept.rules/principle` 的相应可见条目或段落前标明“核心考点：”“扩展理解：”，选用比较表时在对应说明中标注层级。延伸方向明确标“延伸学习（可选）”。这些是显示给学习者的内容标签，不是假定已有独立页签或折叠组件。

核心内容先出现，扩展不能打断通用方法与原题应用的主线。必要时将扩展集中放在核心规则之后；Cornell 先练核心，再选有价值的扩展问题并在 cue 标“扩展理解”。摘要优先保留核心判断路径。浏览器验收实际确认层级标签可见、来源可对应，不能仅检查 JSON 中有文字。

## 每个展示区域各有用途

- `one_liner`：一句话指出本卡核心结论，便于定位。
- `core_concept`：讲清规则、理由、应用条件或关键区别，形成能独立学习的正文。
- `cornell_note.pairs`：每个 cue 提问明确，note 直接回答；覆盖本卡需要练习回忆或判断的内容。按实际内容决定数量，单一事实允许一组。计算卡不能只有“公式是什么”而漏掉条件和结果含义。
- `cornell_note.summary`：压缩本卡的判断路径或关键边界，便于复习。允许重复必要术语和公式，不应原封不动复制整段正文或答案。

禁止把同一段原解析全文复制到结论、唯一 Cornell 答案和摘要。把它们分别改写几个词也不能替代教学组织。反过来，合理的短术语、公式以及复习所需的关键结论复述，不应因文字相同就一概判错。

## 证据与缺口

- **题库原解析**：`question.explanation` 专用于原文件解析转录，页面会标为“题库解析原文”。Agent改写、演算和补充说明放入已有 `question.generated_analysis.explanation`；原文件只有答案没有解析时，`explanation` 留空。题干增加图表转写摘要时明确标为转写。保留来源并说明支持范围，原解析未解释的机制不能冒称原文已有。
- **教辅直接支持**：只有节选直接支持相应结论时才标 `supports`。同一张卡的其他结论仍须分别检查。
- **仅相关材料**：标 `related`；有相同关键词或同属一章不等于支持。
- **Agent 推导/示例**：在可见正文标明，由哪些已核实条件推得；不要冒充教辅原句或真实试题。
- **未核实、缺失或冲突**：在卡片适当位置写明已确认范围和缺口，并纳入交付说明。没有教辅证据可以保留由题库支持的有限卡片，不能虚构证据、页码或拼接出确定答案。

证据元数据沿用现有 `source_id`、`concept_ids`、`relation`、`locator`。原文引用与 Agent 解释分开，PDF 页码使用实际物理页。缺少正确答案的题目不要强塞进要求确定答案的可刷题列表；保留待处理原题及原因，报告计数差异。

## 逐卡审校表

每张卡应留下具体审校记录，至少回答：

1. 知识点范围是否连贯？题目关联是否成立，有没有漏掉关联题的必要考点？
2. 学习者能否完成上表中适用的学习目标？是否只在重复原答案？
3. 公式、条件、分类、版本和数字是否与原文一致？是否需要订正或限定？
4. `supports` 是否直接支持对应结论？`related`、推导和缺口是否如实标明？
5. Cornell 问答是否能用于回忆或应用判断，摘要是否起到复习作用？
6. 扩展是否有明确学习用途和逐项依据，核心/扩展标签是否可见？有无把必要条件移入可选内容，或把扩展误标为原题考点？无扩展时是否出于范围或证据判断，而非漏掉必要讲解？

严重错误、未修正的复制填充或错误关联必须修正后再交付。信息不足可以保留有限内容和待核验状态。程序会拦截整段复制及仅改尾部标点的变体；长段近似重复进入待审，短公式正常复用不据此阻断。程序发现的重复等问题需回到卡片修正；不能通过移除审校记录、改状态或机械同义改写绕过检查。

逐卡在现有 concept 中写入可选审校记录，兼容旧 v2 但新生成的真实卡片必须完成此记录：

```json
"content_review": {
  "reviewer": "agent",
  "status": "reviewed",
  "rationale": "已对照关联题和原页检查定义、公式条件与两组自测；教辅节选直接支持本卡规则。"
}
```

`rationale` 必须是针对本卡的非空、非占位说明，写清检查依据或未解决事项，不能批量复制“已检查”。示例文字不能作为真实审校证据。`status` 仅允许 `reviewed`（已完成 Agent 审校）、`needs_revision`（仍需修订）、`limited`（保留有限内容并明确证据限制）。`reviewed` 不能绕过硬阻断或正文缺失。旧 v2 缺此字段仍可读取，但默认待审，不能声称内容完成。

包级报告区分 `structural_status` 与 `content_status`。内容状态为 `blocked`、`review_required`、`agent_reviewed` 或 `limited`，`quality_status` 随内容状态；`agent_reviewed` 只表示 Agent 的审校记录及确定性检查满足要求。未由本地程序执行浏览器检查时 `browser_status` 为 `not_checked`，Agent 实际浏览器验收需另行如实记录。fixture 是显式演示，不冒充真实材料审校。

结构检查、Agent 内容审校、浏览器验证和人类审阅分别报告。Agent 自报已审阅不等于独立事实认证；未进行人类审阅就不能写“人工通过”。浏览器验证除跳转外，应实际阅读一组代表卡片，确认正文、自测、教辅节选和原页对应。
