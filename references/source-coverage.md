# 原始资料覆盖、生成后核对与漏包补救

## 1. 在筛选和复制资料前锁定用户输入范围

先记录用户明确指定的原始目录。用户指定“快考通导入”时，就以该目录为边界，不扩大到父目录；用户指定多个原始文件夹时，应全部记录，不能改用只含部分文件的工作目录。无需为已经明确的范围重复询问。

在开始阅读前建立 `source-inventory.json`。`input_scope.root` 写解析后的绝对目录，`scopes` 写传给 CLI 的相对子目录列表；检查整个目录时写 `["."]`，CLI 不传 `--source-scope`。例如：

```json
{
  "input_scope": {"root": "/absolute/user-input", "scopes": ["."]},
  "files": [
    {"path": "教材.pdf", "decision": "pending"},
    {"path": "速记/卡片.pdf", "decision": "pending"}
  ]
}
```

逐层遍历子目录，按扫描器支持的 PDF、DOC/DOCX、TXT/MD、XLS/XLSX 登记全部原件。题库 JSON 与图片附件另按题库契约核对，不能把上述文档扫描数称为目录全部文件数。程序会在覆盖报告中注明扫描扩展名。不得只列已选中的教辅。`pending` 不能通过生成检查。

阅读后把每个文件改为 `included` 并填写 `source_id`，或 `excluded` 并填写具体 `reason`。入包教辅无证据时填写 `no_evidence_reason`。重复版本、README、与本次考试无关的资料可以说明原因后排除；“无文字层”“时间不够”“尚未读完”属于未完成，必须继续处理或明确报告受阻，不能包装成正常排除。

## 2. 生成前后两次核对

生成入口继续使用 `--source-root`、`--source-inventory`，必要时加 `--source-scope`。有 `input_scope` 时，命令行与其不一致会失败。

- **生成前**：原始文档集合与清单一一对应；记录每份原件（含排除文件）的 SHA-256；入包文件必须与 sources 哈希相同。
- **生成后、交付前**：重新扫描同一原始目录，检查新增/删除/修改文件和清单变化；对比已校验输入、落盘 JSON 和 HTML 中实际嵌入的数据；核对教辅来源、证据与考点边、节选、关系类型、原文件链接及物理页；检查包内原文件哈希和页图文件存在且非空。
- **失败行为**：临时包不会发布为正式输出目录；保留 `<output>.post-generation-check.json` 或 `<output>.source-coverage.json`。报告中的 findings/errors 是待修复清单，不能只修改报告状态。
- **成功产物**：`reports/source-coverage.json`、`reports/post-generation-check.json`、`data/source-inventory.json`。后者是生成时冻结的清单。

验收已生成包或准备替换线上包前，运行只读复核：

```bash
python3 scripts/verify-package.py /absolute/package-directory
```

退出码 0 表示本次结构与资源复核通过；非 0 必须读取报告。旧包没有冻结清单或原件哈希时，只能得到 `limited`，不能把之前的生成前 passed 当成生成后通过。原始目录已经移走时也不能声称原始覆盖复核通过。

这些检查不证明 OCR 字词正确、证据确实支持主张或图片显示正常。仍需打开学习页，抽查新增教辅的节选、原页图、原文件跳转和学习记录；公式、表格、缺字 OCR 应对照原图校正。浏览器受限时明确写待验，不能用文件存在替代可见验收。

## 3. 发现漏包后 Agent 必须执行的修复流程

发现漏读、漏登记、漏关联、漏复制或漏渲染时，继续完成已授权的修复，不只返回“发现问题”的报告：

1. 保留用户输入范围、现有包和学习记录；列清漏项及发生阶段。
2. 回到漏项原件读取。扫描页使用视觉/OCR 后核对；无法读取时记录具体阻塞条件。
3. 补写/修正清单、sources、teaching_evidence 和考点双向关联；只把确实支持主张的内容标为 supports，其余按相关性或不足如实标注。不得为增加多源数量硬挂材料。
4. 保留已有题目、案例、考点与证据 ID；新材料使用新增稳定 ID。修正 agent-content 和导致漏项的源代码/生成脚本，不能只补页面。
5. 在新目录重新生成，重跑生成前和生成后检查，再执行上述只读复核与浏览器抽查；失败则回到相应步骤继续修复。
6. 验收通过后按用户授权替换现有包，验证原 URL 指向、错题、作答与草稿；不清空数据库，不改写学习记录。用户要求暂不打包 dist 时不重打发布 ZIP。
7. 向用户补报：每份文件处置、修复前后来源/证据数量、排除理由、仍未解决项、实际测试与浏览器验收范围。分别报告教辅页图和案例截图数量。有受阻或待验项时不能称为“全部完成”。

不得通过缩小根目录/子目录、删除清单漏项、将未读文件改成无理由排除、添加无关关联或手工改 passed 绕过检查。程序只核对记录和产物，用户范围是否真实、排除理由是否合理和内容语义仍由 Agent 审核负责。
